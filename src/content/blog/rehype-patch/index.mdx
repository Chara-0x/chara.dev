## Slide 2: “What’s a Qubit (Classical vs Quantum)”

**Title:** What’s a Qubit?
**Subtitle (below the title):** Going from a Classical Bit to a Quantum Bit

---

1. **Classical Bit vs. Qubit (High­-Level)**

   * A *classical bit* can only be in one of two definite states:

     $$
       \text{Bit} \;=\; 0\quad\text{or}\quad 1.
     $$
   * A *qubit* can be in a **combination** of both 0 and 1 *simultaneously* (until measured).  In Dirac notation:

     $$
       \lvert \psi\rangle \;=\; \alpha\,\lvert0\rangle \;+\; \beta\,\lvert1\rangle,\quad \alpha,\beta\in\mathbb{C},\;|\alpha|^2 + |\beta|^2=1.
     $$
   * Whereas a classical bit is “*either 0 or 1*,” a qubit is a normalized vector in a 2-dimensional complex space.

---

2. **State Space Comparison**

   * **Classical bit space:** Two points ${0,1}$ (no “in‐between”).
   * **Qubit state‐space:** Every *unit‐length* vector $(\alpha,\beta)^T\in\mathbb{C}^2$ lives in a continuous family of states—represented visually by the entire surface of a sphere (the Bloch sphere, to come).
   * As $\alpha$ and $\beta$ vary continuously (subject to $|\alpha|^2+|\beta|^2=1$), you sweep out a full sphere of possible pure states.

---

3. **Measurement vs. Superposition**

   * If you “measure” a classical bit, you simply read 0 or 1.
   * If you “measure” a qubit in the $ \lvert0\rangle,\lvert1\rangle$ basis, you get 0 with probability $|\alpha|^2$ and 1 with probability $|\beta|^2$, and the qubit collapses to the corresponding basis state.
   * **Key point:** Prior to measurement, there is no single “0 or 1” – the qubit genuinely “lives” in a superposition $\alpha\lvert0\rangle + \beta\lvert1\rangle.$

---

4. **Why “Quantum” Adds Power**

   * Because we can prepare qubits in *superpositions*, then apply **unitary transformations** (rotations in that 2D complex space) before measuring, we can manipulate interference patterns among probability amplitudes ($\alpha,\beta$).
   * Multiplying qubits into multi-qubit registers gives rise to a $2^n$-dimensional state space—far richer than $2^n$ classical configurations.
   * *Interference* (constructive or destructive) among amplitudes is what lets quantum algorithms “cancel out” bad answers and amplify good ones.

---

5. **Physical Implementations**

   * Any two‐level quantum system can serve as a qubit:

     * Electron spin ↑/↓ in a magnetic field
     * Polarization of a photon (horizontal/vertical)
     * Energy levels of a superconducting circuit (|g⟩, |e⟩)
   * We encode “$\lvert0\rangle$” in one physical level, “$\lvert1\rangle$” in the other.  All manipulations are then unitary rotations in that two‐level subspace.

---

6. **Preview: The Bloch Sphere**

   * Although every pure qubit is $\alpha\lvert0\rangle + \beta\lvert1\rangle$ with $|\alpha|^2+|\beta|^2=1$, we can *remove* one overall phase (global phase) and parameterize the remaining degrees of freedom by two real angles $(\theta,\phi)$.
   * This two‐parameter family maps to the surface of a unit sphere in $\mathbb{R}^3$ (the Bloch sphere).
   * **Slide 3** (your next slide) will show exactly how $\theta,\phi$ correspond to the usual spherical coordinates on the Bloch sphere.

---

*(End of Slide 2.)*

## Slides on Superposition & Interference

Below is a short multi‐slide progression that you can insert right before diving into Shor’s algorithm. The goal is to give the audience a clear intuition for what superposition and interference mean and how they can be used to *extract global properties* (like a period) from a function.

---

### Slide X: “Superposition: Doing Many Things at Once”

1. **What Is Superposition?**

   * If $|\psi_1\rangle$ and $|\psi_2\rangle$ are valid qubit states, then

     $$
       c_1\,|\psi_1\rangle + c_2\,|\psi_2\rangle  
       \quad\text{is also a valid state, provided }|c_1|^2 + |c_2|^2 = 1.
     $$
   * In the computational basis, for a single qubit:

     $$
       |\psi\rangle = \alpha\,|0\rangle + \beta\,|1\rangle.
     $$
   * For $n$ qubits, you can prepare

     $$
       \frac{1}{\sqrt{2^n}}\sum_{x=0}^{2^n - 1} |x\rangle,
     $$

     which is an equal superposition over all $2^n$ classical bit‐strings.

2. **Key Point about Superposition**

   * A quantum register can “represent” all $2^n$ basis states simultaneously (with complex amplitudes).
   * Until you measure, you don’t “pick one” – the full vector of amplitudes evolves unitarily.

3. **Visual Intuition (Optional picture)**

   * Show a 2‐bit register going from $|00\rangle$ → Hadamard ⊗ Hadamard → $(|00\rangle + |01\rangle + |10\rangle + |11\rangle)/2$.
   * Emphasize: We have not “copied” a bit; we have *created* a new state whose amplitudes allow us to handle four possibilities at once.

---

### Slide X+1: “Interference: Adding Amplitudes, Not Probabilities”

1. **Born Rule Reminder**

   * If the state is $|\psi\rangle = \sum_x c_x,|x\rangle$, then measuring yields outcome $x$ with probability $|c_x|^2$.
   * If two computational paths lead to the *same* basis state $|x\rangle$, their amplitudes **add** (before squaring).

2. **Constructive & Destructive Interference**

   * Suppose two different amplitudes $c_{x}^{(1)}$ and $c_{x}^{(2)}$ both feed into the basis state $|x\rangle$.  Then the *combined amplitude* is

     $$
       c_x^{(\text{total})} \;=\; c_{x}^{(1)} + c_{x}^{(2)}.
     $$
   * Probability to observe $x$ becomes

     $$
       |c_x^{(\text{total})}|^2  \;=\; |\,c_{x}^{(1)} + c_{x}^{(2)}\!|^2.
     $$
   * If $c_{x}^{(1)}$ and $c_{x}^{(2)}$ have **the same phase**, they add up (constructive interference) → bigger $|c_x|^2$.
   * If they have **opposite phase** ($180^\circ$ out of phase), they cancel (destructive interference) → possible zero amplitude.

3. **Why It Matters**

   * We can engineer a quantum circuit so that “wrong” answers interfere destructively (their amplitudes cancel) while “right” answers interfere constructively (amplitudes reinforce).
   * After such interference, measuring is very likely to produce one of the “right” answers.

---

### Slide X+2: “Putting It Together: Period-Finding Intuition”

1. **Goal of Period Finding**

   * We have a function $f:\{0,1,\dots,Q-1\}\to\{0,1,\dots\}$, promised to be periodic with some unknown period $r$.  That is,

     $$
       f(x + r) = f(x)\quad\text{for all }x.
     $$
   * Classically, discovering $r$ takes $\mathcal{O}(r)$ or more evaluations in the worst case.

2. **Quantum Trick: Superpose All Inputs**

   * **Step 1:** Prepare a uniform superposition in the first register:

     $$
       \frac{1}{\sqrt{Q}} \sum_{x=0}^{Q-1} \;|x\rangle\,|0\rangle.
     $$
   * **Step 2:** Compute $f(x)$ into a second register, producing

     $$
       \frac{1}{\sqrt{Q}}\sum_{x=0}^{Q-1}\;|x\rangle\,|\,f(x)\rangle.
     $$
   * Because $f(x)$ repeats every $r$ steps, each value $f(x)$ appears in exactly $\frac{Q}{r}$ different inputs (assuming $r\mid Q$).

3. **Measurement of the Second Register**

   * If we now measure $|f(x)\rangle$ (the second register), we collapse the state to “all $x$ that share this measured value.”  Concretely, we get:

     $$
       \frac{1}{\sqrt{Q/r}} \sum_{k=0}^{(Q/r)-1} 
       \Bigl|\,x_0 + k\,r\Bigr\rangle \;|\underbrace{f(x_0)}_{\text{fixed}}\rangle,
     $$

     for some random $ x _ 0 \in {0, \dots ,r-1 }$.  Notice that the *first register* is now an equal superposition of the $r$ inputs ${,x_0,,x_0 + r,,x_0 + 2r,\dots}$.

4. **Key Observation: A Sum of Equally Spaced Inputs**

   * The remaining first‐register state (unnormalized) is

     $$
       \sum_{k=0}^{(Q/r)-1} \bigl|\,x_0 + k\,r\bigr\rangle.
     $$
   * Because this is a sum over $k$ that differ by exactly $r$, it has the form of a “periodic impulse train” in the computational‐basis index.  If you now perform a Quantum Fourier Transform (QFT) of size $Q$, these equally spaced spikes in “position‐space” turn into *sharp peaks* in “frequency‐space” at integer multiples of $Q/r$.  Measuring the QFT output then yields a value that, with high probability, reveals a multiple of $Q/r$, from which you can deduce $r$.
   * (You said: “No need to explain QFT in detail, just assume it exists.”)

5. **Superposition + Interference = Period**

   * The *superposition* over ${x_0 + k,r}$ ensures that only those endpoints of spacing $r$ remain—everything else has been “erased” by the measurement of $f(x)$.
   * The **interference** generated by the QFT then turns that periodic set of spikes into concentrated amplitudes at integer multiples of $Q/r$.  A single measurement in the Fourier domain yields (with high probability) some value $m\approx,Q\cdot \ell/r$ for some $\ell\in{0,1,\dots,r-1}$.  From $\tfrac{m}{Q}\approx \tfrac{\ell}{r}$ you can recover $r$ by continued‐fraction expansion.

---

## Slides on Shor’s Algorithm (Quantum Period-Finding Part)

Below is a suggested sequence of 2–3 slides about **Shor’s algorithm**, focusing on what happens *on the quantum computer*—namely, how it finds the period $r$ of the function $f(x) = a^x \bmod N$.  We deliberately **skip** any detailed derivation of the Quantum Fourier Transform. In your actual deck you can point a single slide to “(QFT details omitted—see reference).”

---

### Slide Y: “Shor’s Algorithm – The Period-Finding Subroutine”

1. **Problem Statement (Integer Factoring → Period Finding)**

   * To factor a composite integer $N$, pick a random $a\in{2,\dots,N-1}$ coprime to $N$.
   * Define the function

     $$
       f(x) \;=\; a^x \;\bmod\; N.
     $$
   * $f(x)$ is *periodic* with some period $r$ (the *order* of $a$ modulo $N$):

     $$
       f(x+r) = f(x)\quad (\bmod\,N).
     $$
   * Once $r$ is known and is even, then $a^{r/2}\pm1$ (with high probability) produce a nontrivial factor of $N$.

2. **Quantum Part: Finding $r$ in One Go**

   * We want to find $r$ *exponentially faster* than classical methods by exploiting superposition and interference.
   * **Registers needed:**

     1. **Input register** of $n$ qubits (large enough to hold integers from 0 to $Q-1$, where $Q$ is some power of 2 with $Q>N^2$).
     2. **Output (work) register** of $m$ qubits (enough to hold values $a^x \bmod N$).

---

### Slide Y+1: “Step 1: Create an Equal Superposition over ${0,\dots,Q-1}$”

1. **Initialize Both Registers**

   * First register $\bigl|0\bigr\rangle^{\otimes n}$.
   * Second register $\bigl|0\bigr\rangle^{\otimes m}$.

2. **Apply Hadamards to the First Register**

   * After $n$ parallel Hadamard gates,

     $$
       H^{\otimes n} 
       \;\bigl|0\rangle^{\otimes n}\;\otimes\;\bigl|0\rangle^{\otimes m} 
       \;=\; 
       \frac{1}{\sqrt{Q}} \sum_{x=0}^{Q-1} |\,x\,\rangle \;\otimes\;\bigl|0\bigr\rangle.
     $$
   * Now the first register “holds” a uniform superposition of all integers $0,1,\dots,Q-1$.

---

### Slide Y+2: “Step 2: Compute $a^x \bmod N$ in Superposition”

1. **Modular Exponentiation Unitary**

   * Define a unitary $U_f$ that does

     $$
       U_f\,:\;|\,x\,\rangle\,|\,0\,\rangle \;\mapsto\; |\,x\,\rangle\,\bigl|\;a^x \bmod N\;\bigr\rangle.
     $$
   * We apply $U_f$ to the two registers.
   * Because we started with $\frac{1}{\sqrt{Q}}\sum_x |x\rangle,|0\rangle$, after $U_f$ we get:

     $$
       \frac{1}{\sqrt{Q}}\sum_{x=0}^{Q-1} \;|\,x\,\rangle\,\bigl|\;a^x \bmod N\;\bigr\rangle.
     $$

2. **Why This Is Crucial**

   * Now each basis‐index $x$ in the superposition “carries along” its corresponding $a^x \bmod N$ in the second register.
   * But $a^x \bmod N$ *repeats* every $r$ steps (since $r$ is the order of $a$).
   * Therefore the joint state is an equal superposition over $Q$ pairs $\bigl(x,;a^x \bmod N\bigr)$, with $x$ running from $0$ to $Q-1$.

---

### Slide Y+3: “Step 3: Measure the Second Register → Collapse to a Periodic Superposition”

1. **Measure the Second Register (Compute Output)**

   * We measure the second register in the computational basis.  Suppose the outcome is $y_0 = a^{x_0} \bmod N$.
   * Because $f(x)=a^x\bmod N$ takes the same value $y_0$ for all $x$ of the form $x_0 + k,r$, the measurement collapses the input register onto an equal superposition of all those $x$ that satisfy $f(x)=y_0$.

2. **Post-Measurement State of the First Register**

   * Immediately after measuring $|,y_0,\rangle$ on the second register, the first register becomes (up to normalization):

     $$
       \sum_{k=0}^{(\,Q/r\,)-1} 
       \bigl|\;x_0 + k\,r\;\bigr\rangle, 
       \quad\text{where }x_0\in\{0,\dots,r-1\}\text{ was “the $k=0$ solution.”}  
     $$
   * In other words, the first register is now an equal superposition of all integers spaced by exactly $r$.

3. **Key Insight: A “Periodic Impulse Train” over ${0,\dots,Q-1}$**

   * Graphically, if you imagine plotting an amplitude at each integer $x\in{0,\dots,Q-1}$, you only have “spikes” at $x_0,,x_0+r,,x_0+2r,\dots$.
   * Everything else has been “zeroed out” by the measurement.
   * This periodic structure (spacing exactly $r$) is what will allow the QFT to reveal $r$ via interference.

\*(At this point, you can have a single slide labelled “(Assume we now apply the QFT to this periodic superposition.  By measuring the QFT output, we obtain a result whose probability is peaked sharply around integer multiples of $Q/r$.  Using continued fractions on that measured peak gives $r$.)”)

---

### Slide Y+4: “Step 4: (Assume QFT) → Extract the Period”

1. **Assume a Perfect Quantum Fourier Transform**

   * We do not derive it here.  Simply:

     $$
       \text{QFT}_Q\,:\;|\,x\,\rangle \;\mapsto\; \frac{1}{\sqrt{Q}}
       \sum_{k=0}^{Q-1} e^{2\pi i\,x\,k/Q}\;|\,k\,\rangle.
     $$
   * When you feed in a uniform superposition of ${x_0 + k,r}$, the QFT outputs large amplitudes only at $k$ values that satisfy

     $$
       \frac{k}{Q} \approx \frac{\ell}{r},\quad
       \ell = 0,1,2,\dots,r-1.
     $$
   * Thus measuring the QFT register will (with high probability) give you some integer $k^*$ so that $k^*/Q$ is very close to a rational $\ell/r$.

2. **Recovering $r$ via Continued Fractions**

   * Take the measured $k^*$ and form the fraction $\frac{k^*}{Q}$.
   * Use the classical continued‐fraction algorithm to find a fraction $\ell/r$ that approximates $k^\*/Q$ with small denominator.  With high probability you’ll recover the *correct* $r$.

3. **Summary of the Quantum Period-Finding Subroutine**

   1. Create $\tfrac{1}{\sqrt{Q}}\sum_{x=0}^{Q-1} |x\rangle,|0\rangle$.
   2. Compute $|x\rangle,|0\rangle \mapsto |x\rangle,|a^x \bmod N\rangle$.
      → Joint superposition over all $(x,f(x))$.
   3. Measure the second register $\Rightarrow$ first register collapses to

   $$
   \tfrac{1}{\sqrt{Q/r}}\sum_{k=0}^{(Q/r)-1} |\,x_0 + k\,r\,\rangle.
   $$

   4. Apply QFT on the first register $\Rightarrow$ amplitude peaks at multiples of $Q/r$.
   5. Measure; use continued fractions to infer $r$.

4. **Once $r$ Is Known (and Even)**

   * Check if $a^{r/2} \equiv \pm 1 \pmod{N}$.
   * If $a^{r/2} \not\equiv -1\pmod{N}$, then $\gcd\bigl(a^{r/2}\pm1,;N\bigr)$ gives a nontrivial factor of $N$.
   * If $a^{r/2}\equiv -1\pmod{N}$ or $r$ is odd, pick a new random $a$ and repeat.

*(End of Shor’s quantum‐period module.)*

---

### Optional Slide Z: “Why Period-Finding Outpaces Classical”

1. **Classical Approach to Period Finding**

   * You can evaluate $f(x)=a^x \bmod N$ point by point, searching for the smallest positive $r$ such that $f(x+r)=f(x)$.
   * This takes $\mathcal{O}(r)$ evaluations in the worst case, and $r$ can be as large as $\mathcal{O}(N)\approx 2^n$.

2. **Quantum Speed-Up**

   * The entire “search over ${0,\dots,Q-1}$” happens at once in a single superposition.
   * The interference after the QFT pinpoints $r$ in one shot (up to classical post‐processing with continued fractions).
   * Overall, the quantum subroutine runs in polynomial time in $n=\log N$ (dominated by the cost of modular exponentiation in superposition, which is $\mathrm{poly}(n)$).

3. **Conclusion:**

   * Shor’s algorithm factors an $n$-bit integer in time $\mathrm{poly}(n)$, exponentially faster than the best known classical algorithms ($\exp(\sqrt{n})$-type).

## A problem (about dead maintainers)

This post talks about changes I've made to astro-erudite in v1.3.0!

I recently found myself caught between two syntax highlighting packages that I absolutely needed for astro-erudite. On one hand, the current template uses [rehype-pretty-code](https://rehype-pretty.pages.dev/) as its main syntax highlighting solution, but due to issues with its inherent implementation and missing features that I needed, I had created a bunch of custom transformers to make it do what I wanted, and the whole setup was getting unwieldy. I then discovered [Expressive Code](https://expressive-code.com/), which had everything I wanted out of the box—collapsible code sections, terminal and editor frames, gutter comments—it was perfect! Well, almost perfect.

The primary issue was that Expressive Code doesn't support inline syntax highlighting, which is non-negotiable for me since I need my inline code snippets to look as good as my code blocks (so I could do stuff like `console.log("Hello, world!".split('').reverse().join('')){:js}`). So I opened a feature request at [expressive-code/expressive-code#250](https://github.com/expressive-code/expressive-code/issues/250) and the maintainer seemed interested, saying they'd get around to it eventually. Implementing this feature is a lot easier said than done though, and I summarized it well in another thread:

> [@jktrn](https://github.com/rehype-pretty/rehype-pretty-code/issues/247#issuecomment-2619869436): [...] expressive-code is already interested in implementing inline code support, but it would be a bit nuanced to add since it has to:
> 
> - allow existing plugins to continue working normally with block-level code (without breaking changes),
> - enable new plugins to explicitly declare support for inline code,
> - and provide ways for plugins to distinguish between inline and block-level code processing.

However, I needed a solution immediately. My first thought was to use both packages together—Expressive Code for block code and rehype-pretty-code for inline code. However, importing both at the same time caused everything to break spectacularly.

## The hunt for a solution

Digging into the rehype-pretty-code docs, I noticed they had a `bypassInlineCode{:js}` option that lets you skip inline code highlighting (it was actually added in a really recent update). But what I needed was the opposite, which would be a way to make it only handle inline code and bypass blocks entirely.

So I opened a feature request at [rehype-pretty/rehype-pretty-code#247](https://github.com/rehype-pretty/rehype-pretty-code/issues/247) for a theoretical `bypassBlockCode{:js}` option. I got no response, since the repository seemed unmaintained for a bit since it seems like the maintainer has moved onto other projects.

Fast forward a few months, and user [@kelvindecosta](https://github.com/kelvindecosta) comments on my issue:

> [[@kelvindecosta]](https://github.com/rehype-pretty/rehype-pretty-code/issues/247#issuecomment-2610536000): Hey [@jktrn](https://github.com/jktrn), did you figure out a workaround for this? I'm interested in setting this up alongside expressive-code.

After I replied that I hadn't figured out a workaround yet, they sent me a brilliantly hacky solution a couple days later:

> [[@kelvindecosta]](https://github.com/rehype-pretty/rehype-pretty-code/issues/247#issuecomment-2619666231): Hey again @jktrn, I have found an unconventional way to achieve this.
> 
> If you're using pnpm or bun, you can use their patch functionality to customize the contents of the `node_modules/rehype-pretty-code` package.
> 
> I only recently learned about this feature, and it is a good workaround for the time being. Here are the steps:
> 
> 1. Run `pnpm patch rehype-pretty-code`. This will instruct you to edit the files in a certain directory.
> 2. Patch out the `isBlockCode{:js}` function to always return `false{:js}`. This will instruct the plugin to not process any block code elements.
> 3. Run `pnpm patch-commit <path/to/files>`. This will create a nice patches folder with the right changes.

## Performing surgery on node_modules

This happened to be exactly what I needed! I went into my `node_modules` directory and made the changes manually:

```js title="node_modules/rehype-pretty-code/dist/index.js" startLineNumber=18 ins={9} del={8}
function isInlineCode(element, parent, bypass = false) {
  if (bypass) {
    return false;
  }
  return element.tagName === "code" && isElement(parent) && parent.tagName !== "pre" || element.tagName === "inlineCode";
}
function isBlockCode(element) {
  return element.tagName === "pre" && Array.isArray(element.children) && element.children.length === 1 && isElement(element.children[0]) && element.children[0].tagName === "code";
  return false;
}
```

From here, I ran `npx patch-package rehype-pretty-code`, which created a `patches/rehype-pretty-code+0.14.1.patch` file with the changes I made:

```diff title="patches/rehype-pretty-code+0.14.1.patch"
--- a/node_modules/rehype-pretty-code/dist/index.js
+++ b/node_modules/rehype-pretty-code/dist/index.js
@@ -22,7 +22,7 @@ function isInlineCode(element, parent, bypass = false) {

 }

-  return element.tagName === "pre" && Array.isArray(element.children) && element.children.length === 1 && isElement(element.children[0]) && element.children[0].tagName === "code";
+  return false;
 }

```

This simple modification forces rehype-pretty-code to completely ignore block code elements by always returning `false{:js}` from the `isBlockCode{:js}` function. Now Expressive Code handles all block code formatting, while rehype-pretty-code still beautifully handles my inline code. And just like that, they're working in perfect harmony!

## Please don't perform surgery on your node_modules

Absolutely do not do this for production sites (your personal blog does not count =￣ω￣=). Directly patching node modules is generally discouraged because patches can break with updates and create maintenance headaches down the road.

But sometimes, when you're working at the bleeding edge of web development, temporary solutions like this become necessary. The better approach would be to just wait for Expressive Code to implement inline syntax highlighting. But, since it'll take a while for reasons aforementioned, I'll stick with my janky solution. This patch buys me time until either rehype-pretty-code gets maintained again and implements the feature properly, or Expressive Code adds inline code support.

In the meantime, astro-erudite now has both beautiful code blocks and inline syntax highlighting. And now it's available for all of you to use!
